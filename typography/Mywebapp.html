What is CSS Position?

CSS position controls how an element is placed on a page. It lets you move elements, overlap them, keep them visible while scrolling, or attach them to a specific location.
Why it is used

Create menus, floating buttons, badges, overlays, popups, sticky headers, and custom layouts.

Basic Syntax

position: relative;
top: 20px;
left: 10px;

Position values

static, relative, absolute, fixed, and sticky.

.box { position: relative; top: 20px; left: 10px; }
02 · Default Value

Position: Static

position: static is the default value for every HTML element. Static elements follow the normal document flow and do not respond to top, right, bottom, or left.
Characteristics

✓ Default position value
✓ Stays in normal page flow
✓ Cannot be moved using top, left, right, or bottom
✓ Does not create a positioning reference for children

Output
STATIC BOX

This box remains where normal page flow puts it.

.box { position: static; top: 50px; /* Has no effect */ }
03 · Offset from Original Place

Position: Relative

position: relative keeps an element in the normal document flow, but allows you to move it visually from its original position using top, right, bottom, or left.
How it moves

The original space remains reserved. The element shifts visually, but surrounding elements behave as though it is still in its original location.

Position: Absolute

position: absolute removes an element from the normal document flow. It is positioned relative to its nearest ancestor that has a position value other than static.
Parent positioning

Set the parent to position: relative. Then the absolute child can use top, right, bottom, and left values inside that parent.

01 · Introduction

What is Express.js?

Express.js is a fast, minimal, and flexible Node.js web framework. It provides a robust set of features for building web and mobile applications. Express makes it easy to create servers, define routes, handle HTTP requests and responses, and use middleware.
Why Express?

✅ Minimal and unopinionated
✅ Fast routing system
✅ Huge middleware ecosystem
✅ Easy to learn and use
✅ Powers millions of apps

Install Express

npm init -y
npm install express

02 · Basics

Express Basics

An Express server needs three things: require express, create the app, and listen on a port. Routes define what happens when a user visits a URL.
⚡ Your Practiced Code

This is the exact code you wrote — a server on port 3000 with a GET route.

const app = require('express')(); const PORT = 3000; app.listen(PORT, () => console.log(`Server is running on port ${PORT}`)); app.get('/getRequest', (req, res) => { res.send('Hello this is a GET Method'); });
app.get()

Handles HTTP GET requests at a specific route path.

req

The request object — contains URL, headers, body, params.

res.send()

Sends a response back to the client (text, HTML, JSON).

04 · Multi-Server

Running Two Servers

You can run multiple Express servers on different ports at the same time. Each port is a separate "door" into your machine. This is useful for microservices or separating frontend and backend.
// server1.js — Port 3000 const app1 = require('express')(); app1.get('/', (req, res) => { res.send('Server 1 — Port 3000'); }); app1.listen(3000, () => console.log('Server 1 on :3000') );
// server2.js — Port 3001 const app2 = require('express')(); app2.get('/', (req, res) => { res.send('Server 2 — Port 3001'); }); app2.listen(3001, () => console.log('Server 2 on :3001') );
Run both at once (two terminals)

node server1.js # Terminal 1

07 · Security

Browser Security

Browsers enforce the Same-Origin Policy (SOP) — a page can only freely access resources from the same origin (protocol + hostname + port). This prevents malicious sites from reading your data. Iframes from different origins are restricted.
Same Origin ✅

localhost:3000 → localhost:3000

Same protocol, host, and port. Full access allowed.

Cross Origin ❌

localhost:3000 → localhost:3001

Different port = different origin. Restricted by browser.

Clickjacking ⚠️

Attacker embeds your site in an invisible iframe to trick users into clicking hidden buttons.

// Origins compared: // http://localhost:3000 ← protocol: http, host: localhost, port: 3000 // http://localhost:3001 ← DIFFERENT PORT = different origin // https://localhost:3000 ← DIFFERENT PROTOCOL = different origin
08 · Protection

Preventing Iframes

You can stop other websites from embedding your Express app in an iframe using X-Frame-Options or Content-Security-Policy headers. This protects against clickjacking attacks.
X-Frame-Options values

DENY — Nobody can embed this page

SAMEORIGIN — Only same origin can embed

ALLOW-FROM uri — Only specific URL (deprecated)

CSP frame-ancestors

Modern replacement for X-Frame-Options. More flexible — allows multiple origins to be whitelisted.

const app = require('express')(); // Option 1: X-Frame-Options — DENY app.use((req, res, next) => { res.setHeader('X-Frame-Options', 'DENY'); next(); }); // Option 2: CSP frame-ancestors (modern) app.use((req, res, next) => { res.setHeader( 'Content-Security-Policy', "frame-ancestors 'none'" ); next(); });
09 · Middleware

Helmet.js

Helmet is an Express middleware that automatically sets many security-related HTTP headers for you — including X-Frame-Options, CSP, HSTS, and more. It is the recommended way to secure Express apps.
What Helmet sets automatically

✅ X-Frame-Options: SAMEORIGIN
✅ X-Content-Type-Options: nosniff
✅ Strict-Transport-Security
✅ X-XSS-Protection

✅ Content-Security-Policy
✅ Referrer-Policy
✅ Permissions-Policy
✅ Cross-Origin headers

JavaScript · Asynchronous Programming

JavaScript Promises

A Promise is an object that represents the eventual result of an asynchronous operation. It allows JavaScript to handle operations that take time, such as API requests, timers, database operations, file operations, and login requests.
Promise States

A Promise has three states:

Pending → The operation is still running.

Fulfilled → The operation completed successfully.

Rejected → The operation failed.

Creating a Promise

A Promise is created using the Promise constructor. resolve() is used for success and reject() is used when the operation fails.

const promise = new Promise(function(resolve, reject) {
  let success = true;

  if (success) {
    resolve("Operation successful");
  } else {
    reject("Operation failed");
  }
});
Handling a Promise

then() handles the successful result.

catch() handles errors.

finally() runs after the Promise finishes, whether it succeeds or fails.

promise
.then(function(result) {
  console.log(result);
})
.catch(function(error) {
  console.log(error);
})
.finally(function() {
  console.log("Finished");
});
Promise Chaining

Multiple then() methods can be connected together. The result returned from one then() can be passed to the next then().

async and await

async and await provide a cleaner way to work with Promises. await waits for the Promise result inside an async function.

    const result = await promise;
    console.log(result);
  } catch(error) {
    console.log(error);
  }
}
Multiple Promises

Promise.all() waits for all Promises to complete.

Promise.race() returns the result of the first Promise that settles.

Real-World Usage

Promises are commonly used with APIs, network requests, timers, database operations, file operations, login requests, and other asynchronous tasks.

JavaScript · Events

JavaScript Events

Events are actions or occurrences that happen in a web page. JavaScript can detect these actions and execute a function when they occur. Events are commonly used to make web pages interactive.
Mouse Events

Mouse events occur when the user interacts with an element using the mouse.

click → element is clicked
dblclick → element is double-clicked
mouseover → mouse moves over an element
mouseout → mouse leaves an element

Keyboard Events

Keyboard events occur when the user presses or releases a keyboard key.

keydown → key is pressed
keyup → key is released

Form Events

Form events are used to detect changes and actions performed on form elements.

input → value changes while typing
change → value is changed
submit → form is submitted

addEventListener()

addEventListener() connects an event to a function. It tells JavaScript which event to watch and what function should run when that event occurs.

button.addEventListener("click", function() {
  console.log("Button clicked");
});
Event Object

When an event occurs, JavaScript provides an event object containing information about that event.

event.target → element that triggered the event
event.key → keyboard key that was pressed

button.addEventListener("click", function(event) {
  console.log(event.target);
});
preventDefault()

preventDefault() prevents the browser's default action associated with an event.

For example, it can stop a form from submitting normally or prevent a link from immediately navigating.

form.addEventListener("submit", function(event) {
  event.preventDefault();
});
Remember:

Mouse: click, dblclick, mouseover, mouseout
Keyboard: keydown, keyup
Forms: input, change, submit
Listener: addEventListener()
Event information: event, event.target, event.key
Default behavior: preventDefault()

Media Queries(Mobile-first-approch)

Media queries allow CSS styles to change based on the screen size. They are commonly used to create responsive designs for mobile, tablet, and desktop devices.
Mobile First

Start with styles for mobile devices and use min-width media queries to add styles for larger screens.

Desktop First

Start with styles for desktop devices and use max-width media queries to adjust styles for smaller screens.
