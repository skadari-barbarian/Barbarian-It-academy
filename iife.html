IIFE03 / 12

IIFE: execute code immediately

Immediately Invoked Function Expression is a function expression that runs as soon as it is created.

  • Creates an isolated scope for temporary variables.
  • Useful for one-time setup or initialization.
  • Historically prevents global namespace pollution.
  • Often replaced by ES modules in modern apps.

Core syntax

(function () {
  console.log("Runs immediately");
})();

Parentheses turn the function into an expression; the final () invokes it.

IIFE04 / 12

Why use an IIFE?

🛡️

Private scope

Variables stay inside the IIFE unless explicitly returned.

(() => {
  const apiKey = "private";
  console.log(apiKey);
})();
🚀

Practical initialization

Run startup work once without exporting helper values globally.

(() => {
  const appName = "Portal";
  console.log(`${appName} started`);
})();

Advantage

Encapsulation makes code safer when sharing a page with other scripts—particularly in legacy browser applications.

IIFE05 / 12

IIFE patterns and common mistakes

Passing data and async work

(function (name) {
  console.log(`Hello, ${name}`);
})("Asha");

(async () => {
  const response = await fetch("/api/user");
})();

Avoid these mistakes

  • Forgetting the final invocation parentheses.
  • Using an IIFE where an ES module is clearer.
  • Expecting its private variables outside the scope.
  • Writing overly large IIFEs that hide application flow.

Rule of thumb: use an IIFE for one-off isolation; use modules for reusable architecture.

Function Inputs06 / 12

Parameters vs arguments

Definitions

ParametersArguments
Named placeholders in a function definition.Actual values supplied when the function is called.
Describe what the function expects.Provide the requested data.

Example

function greet(name) { // parameter
  return `Hello, ${name}`;
}

greet("Priya"); // argument

In this call, the value "Priya" is assigned to the parameter name.

Function Inputs07 / 12

How function calls map inputs

Call: createUser("Ravi", "Admin")
→
name = "Ravi"
→
role = "Admin"

Design for safe calls

function discountedPrice(price, discount = 0) {
  return price - price * (discount / 100);
}

discountedPrice(2500, 10);
  • Order matters for positional arguments.
  • Defaults handle optional values safely.

Interview questions

  • What occurs if an argument is missing? The parameter becomes undefined unless a default exists.
  • How do rest parameters work? They collect remaining arguments into an array.
  • When use an object parameter? For multiple related, named options.
Variables08 / 12

const vs let: express intent

🔒

const

A binding that cannot be reassigned. It must be initialized during declaration.

const company = "BluePeak";
// company = "Other"; // TypeError
🔄

let

A block-scoped binding that may be reassigned later.

let status = "Pending";
status = "Approved";

Variables10 / 12

Reassignment, objects, and best practices

const does not freeze an object

const employee = { name: "Meera" };
employee.name = "Mira"; // allowed

// employee = {}; // not allowed

const protects the variable reference—not its object properties.

Professional default

  • Start with const for every variable.
  • Switch to let only if reassignment is genuinely required.
  • Avoid var in new code.
  • Use clear names that communicate whether data is stable or changing.
